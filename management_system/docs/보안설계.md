# BMS 경영관리업무시스템 – 보안 설계서

> 대상: 임직원 개인정보·연봉을 처리하는 사내 시스템, 사용자 5명 이하, **로그인 후 외부 접속 허용**
> 기준: 개인정보 보호법 및 「개인정보의 안전성 확보조치 기준」, OWASP Top 10

## 1. 보안 구조 한눈에 보기

```
[사용자 브라우저] ──HTTPS(TLS)──▶ [리버스 프록시(HTTPS 종단)] ──127.0.0.1:8100──▶ [BMS 앱]
                                                                                    │
     ① 로그인(아이디+비밀번호) → ② 2단계 인증(OTP) → ③ 권한 확인 → ④ 접속기록       │
                                                                                    ▼
                                          [SQLite DB: 개인정보·연봉 필드 AES-256 암호화]
                                          [마스터키: 별도 secrets 폴더, 별도 백업]
                                          [PDF: NAS \\NAS\BMS\BMS_인사\... (SHA-256 무결성)]
```

## 2. 적용된 보안 조치

| 영역 | 조치 내용 | 관련 기준 |
|------|-----------|-----------|
| **인증** | 개인별 계정(공용계정 없음), 비밀번호 **Argon2id** 해시 저장 | 안전성 확보조치 제5조 |
| **2단계 인증** | TOTP(Google/Microsoft Authenticator) **전원 필수**, 30초 코드·재사용 차단 | 외부 접속 시 안전한 인증수단 (제6조) |
| **비밀번호 정책** | 10자 이상·3종류 조합·아이디 포함 금지, 최초 로그인 시 변경 강제, 90일 주기 변경 | 제5조 |
| **무차별 대입 차단** | 계정별 5회 실패 시 15분 잠금, IP별 15분 20회 실패 시 차단, 계정 존재 여부 비노출 | 제5조 |
| **세션** | 무작위 토큰(쿠키), DB에는 **해시만** 저장, HttpOnly·SameSite=Strict·Secure, 유휴 30분·최대 10시간 자동 만료, 로그인 시 세션 재발급(고정 공격 방지), 비밀번호 변경 시 전 기기 로그아웃 | 제6조 |
| **권한(RBAC)** | 시스템관리자 / 인사·총무담당 / 총무담당 / 조회자 4단계. 총무담당은 인사 개인정보·연봉 비공개, 관인 사용 승인은 관리자만. 조회자는 연봉·연락처·주소·계좌·상벌·휴직(건강·가족) 정보 **비공개(서버에서 제거)**. 규칙에 없는 경로는 기본 거부 | 제5조(최소권한) |
| **암호화(저장)** | 주민등록번호, 생년월일·연락처·이메일·주소·비상연락처(관계 포함)·계좌·비고·퇴사사유, 기술자 자격번호, 등록 초안 추출값, 서명 링크·수신 메일, **연봉 전체**, 계약서·증명서 본문, 상벌 사유·금액, 자녀정보, 차량 운행 행선지, 경조사 비고, OTP 비밀키 → **AES-256-GCM** (위·변조 탐지 포함) | 제7조 |
| **암호화(전송)** | HTTPS 필수(인증서 직접 또는 리버스 프록시), HSTS | 제7조 |
| **키 관리** | 마스터키를 DB와 **다른 폴더**에 보관, 키 없으면 기동 거부(잘못된 키로 덮어쓰기 방지), 별도 매체 백업 안내 | 제7조 |
| **접속기록** | 로그인·로그아웃·실패, **인사기록·연봉·문서 열람**, 등록·수정·삭제, 내보내기를 사용자·IP·일시와 함께 기록. 연봉 금액 등 원문은 기록하지 않음. 관리자 화면에서 조회·CSV 다운로드 | 제8조(1년 이상 보관·월 1회 점검) |
| **CSRF** | Origin 검증 + 세션별 CSRF 토큰(폼·JSON 모두) | OWASP |
| **XSS** | 템플릿 자동 이스케이프, 계약서 치환값 이스케이프, 에디터 HTML **허용목록 정화(nh3)**, CSP(nonce 기반, 인라인 스크립트 금지) | OWASP |
| **보안 헤더** | CSP, X-Frame-Options DENY(클릭재킹), nosniff, Referrer-Policy, Permissions-Policy, Cache-Control no-store(개인정보 화면 캐시 금지), Server 헤더 제거 | OWASP |
| **외부 의존성 제거** | Bootstrap·Chart.js 등 모두 서버 내 보관(외부 CDN 호출 없음) | 공급망 위험 감소 |
| **입력·파일** | 업로드 5MB 제한, CSV 수식 주입 방지, 파일명·경로 이탈 방지, Host 헤더 허용목록 | OWASP |
| **오류 처리** | 사용자에게 상세 오류 비노출(서버 로그에만), API 문서(/docs) 비활성화 | OWASP |
| **문서 무결성** | NAS 저장 PDF의 SHA-256 해시를 DB에 보관, 열람 시 검증(변조 시 차단) | 제7조 |
| **주민등록번호** | 급여·4대보험 신고 등 **법령 근거 업무**에 한해 별도 테이블(`employee_rrn`)에 암호화 저장. 일반 조회·화면·문서·CSV·템플릿에는 나오지 않고 생년월일만 사용. 원문 확인은 인사담당 이상이 버튼을 누를 때만 가능하며 접속기록에 남고 15초 후 다시 가림 | 개인정보보호법 제24조의2 |
| **입사서류 처리** | 서버 안에서만 판독(Windows 내장 OCR, 외부 전송 없음). OCR 원문은 저장하지 않고 추출 항목만 암호화 저장. 등본의 세대원 번호는 본인 생년월일과 대조해 제외 | 제7조 |
| **전자서명** | 링크 토큰 256비트(DB 조회는 해시), 생년월일 6자리 본인 확인 5회 실패 시 잠금, 기본 7일 만료, 발송 후 본문이 바뀌면 서명 불가, 서명 일시·IP·브라우저·문서 해시 기록, 완료본 수정 불가 | 전자문서법 |
| **메일** | TLS 필수(STARTTLS/SMTPS), 비밀번호는 `bms.toml` 이 아닌 secrets 폴더 또는 환경변수, 메일 본문에 개인정보 미기재(증명서는 PDF 첨부) | 제7조 |

## 3. 운영자가 해야 할 일 (시스템 밖)

0. 주민등록번호 처리는 **동의가 아니라 법령 근거**가 있어야 합니다(제24조의2). 처리 목적을 급여·4대보험 등으로 한정하고 개인정보 처리방침·동의서 문구를 노무사와 확인하세요.
1. **HTTPS 구성 전에는 외부 공개 금지** – `python manage.py check` 로 점검
2. 마스터키(`secrets\bms_master.key`)를 **USB 등 별도 매체에 백업**하고 금고 보관 (분실 시 데이터 복구 불가)
3. 서버 VM 디스크에 **BitLocker** 적용, BMS 폴더는 서비스 계정·관리자만 접근(NTFS 권한)
4. NAS 공유폴더 `BMS` 는 **BMS 전용 계정**만 읽기/쓰기, 일반 직원 공유 금지
5. 매월 1회 **접속기록 점검**(관리자 > 접속기록), 퇴사자·업무변경자 계정 즉시 중지
6. 서버 Windows 보안 업데이트, 원격데스크톱(RDP)은 외부에 직접 열지 않기

## 4. 외부 접속 방식 권장 순위

| 순위 | 방식 | 장점 | 비고 |
|------|------|------|------|
| 1 | **VPN 경유** (공유기/NAS VPN, Tailscale 등) | 시스템 자체가 인터넷에 노출되지 않음 | 5명 이하라 운영 부담 적음, **가장 권장** |
| 2 | **Cloudflare Tunnel / Zero Trust** | 공유기 포트 개방 불필요, 접속자 이메일 인증 추가 가능 | 도메인 필요 |
| 3 | 공유기 포트포워딩 + 리버스 프록시(Caddy) + 공인 인증서 | 구성 단순 | 443만 개방, 8100 직접 개방 금지 |
